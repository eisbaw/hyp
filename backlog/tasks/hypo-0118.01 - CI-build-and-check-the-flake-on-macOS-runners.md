## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Part of HYPO-0118 (GitHub #1, https://github.com/eisbaw/hyp/issues/1). Developers here have no Mac, so CI is the only place the Darwin flake outputs actually get built and tested. The issue proposes running the existing `nix flake check -L` job on ubuntu-latest, macos-15 (ARM64) and macos-15-intel.

Locally, the Darwin outputs can only be evaluated (derivations instantiate), not built.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
- `nix flake check --all-systems --no-build` evaluates every Darwin output on Linux; actionlint passes.
- CI uses a matrix of ubuntu-latest, macos-15 and macos-15-intel with fail-fast false.

- First macOS CI run: package, clippy, formatting pass on both Macs; e2e-browser failed (Chromium SIGTRAP/SIGILL at launch).
- Diagnostics (runs 37543820485, 37546891874 on branch macos-debug): Nix sandbox is off on the runners; the headless shell works as runner and as root, and crashes as _nixbld1 even outside Nix. macOS crash report: libxpc _xpc_api_misuse in xpc_connection_set_target_uid, called from AppKit/WindowManagement, uid 351. Nix builds on macOS run as _nixbld users, so the check cannot pass there.
- Fix: the browser-test flake app (packaged hyp) is used by the e2e-browser check on non-Darwin systems; macOS CI runs nix run .#browser-test, plus nix develop -c just build to build hyp in the dev shell. The investigation is recorded in the hyp notebook (H-d8d955e7 and its competitors).
